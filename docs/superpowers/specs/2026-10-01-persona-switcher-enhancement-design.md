# 设计：侧栏画像切换器增强（多赛道运营可发现性）

日期：2026-10-01
状态：已与用户确认的设计稿（待实施）

## 背景与问题

多画像能力在后端与前端均已存在：`profiles/<名字>/` 一目录一画像，侧栏顶部有画像
下拉框（通用模式 / 各画像 / ＋新建画像），每个会话绑定画像，聊天、发布、拆解、技能
页均携带所选画像。但用户反馈"只支持一种画像"——实际原因是**切换入口不可发现**：
`web/frontend/src/components/Sidebar.tsx` 顶部的原生 `<select>` 仅 13px 字号、弱边框，
新用户根本注意不到。

用户目标：运营多种赛道的账号，需要快速在多个画像之间切换。

## 目标

1. 让"可以切换画像"一眼可见。
2. 首次使用时主动告知切换入口的存在。
3. 历史会话能看出属于哪个画像（哪个赛道/账号）。

## 非目标（YAGNI）

- 不改后端 API（`/api/personas` 等已满足需求）。
- 不改画像切换行为：当前对话已有消息时切换画像自动新建对话（`App.tsx`
  `handlePersonaChange` 现有逻辑保留）。
- 热点雷达、账号数据等页面不按画像隔离，不在本次范围。

## 方案选择（已确认）

三个候选：侧栏头像卡（Notion/Slack 风格面板）、全局顶栏切换器、增强现有下拉框。
用户选择**增强现有下拉框**：保留原生 `<select>`，只做样式与引导增强。理由：改动
最小、原生控件键盘与无障碍友好、不新增常驻布局元素。

## 设计

纯前端改动，只涉及两个文件：`web/frontend/src/components/Sidebar.tsx`（下拉框、引导
标记与会话列表渲染）和 `web/frontend/src/styles/index.css`（样式与动画）。`Sidebar`
已持有 `personas`、`selectedPersona`、`sessions` 等全部所需数据，无需改 `App.tsx`
或其它组件。

### ① 下拉框视觉增强

- 高度提升至约 40px，字号 13px → 14px；保留 `appearance: none` 与自定义箭头。
- 左侧渲染头像圆点：画像取名字第一个字符，底色由画像名哈希从 6 色预设色板选取；
  「通用模式」显示灰色实心圆点。头像圆点用包裹层实现（`select` 自身无法内嵌元素）：
  外层 `.persona-field` 相对定位容器 + 内层绝对定位圆点 + `select` 左内边距腾出空间。
- 色板（6 色，写死在 `Sidebar.tsx` 常量）：与现有主题色系协调的 6 个背景色，深色
  主题下需可辨（实现时对照 `index.css` 的 CSS 变量取值）。
- `＋ 新建画像…` 选项、禁用逻辑（当前会话已有消息时禁用并提示）全部保留。

### ② 首次引导高亮

- localStorage 键：`easel_persona_hint_seen`（值 `"1"`）。
- 显示条件：未看过 且 `personas.length > 0`。
- 表现：下拉框外圈 accent 色呼吸光晕（CSS animation，`box-shadow` 脉动）；框下方
  一行 12px 次要文字色提示「运营多个账号？在这里切换画像」。
- 消除时机：用户首次点击（`onMouseDown`/`onFocus` 任一触发即可）下拉框时写入标记，
  提示与光晕立即消失，此后永不出现。

### ③ 会话列表画像标记

- `Sidebar.tsx` 的会话条目（`renderItem`）右侧（归档按钮之前）加头像小圆点，复用 ①
  的色板与首字符逻辑；`title` 显示「画像：XXX」；通用模式会话（无 `persona` 字段）
  不显示圆点。
- 圆点纯展示，不响应点击（点击语义仍属于会话条目本身的选中/展开操作）。

## 数据与状态

- 画像列表：沿用 `App.tsx` 已有的 `personas: PersonaItem[]`（`{ name, description }`），
  不新增请求。
- 引导标记：仅 localStorage，无后端状态。
- 会话画像：沿用 `ChatSession.persona`，不新增字段。

## 错误处理

- 画像名哈希取色对任意字符串稳定；空名不可能出现（列表来自目录名）。
- localStorage 不可用（隐私模式/quota）：try/catch 包裹，此时不显示引导提示（不打扰
  优先），功能本身不受影响。

## 测试与验收

- `npm run build`（`web/frontend/`）通过。
- 手动验收：
  1. 已有画像时刷新页面：下拉框显示头像圆点与画像名，首次可见呼吸光晕与提示文字。
  2. 点击下拉框一次后刷新：提示与光晕不再出现。
  3. 切换画像：新会话正常携带画像（发消息后 Agent 收到画像前缀，后端日志/行为可见）。
  4. 历史会话列表：绑定画像的会话显示对应颜色圆点，通用模式会话无圆点。
  5. 当前会话已有消息时，下拉框仍按现有逻辑禁用并提示。
- 现有自动化测试不受影响（本次不涉及后端）。
